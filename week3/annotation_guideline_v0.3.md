# 주석기준서 v0.3 (3주차 제출물 ② — 수정본, 2026-11-20)

대상: 지하 콘크리트 구조물 표면 영상 · 방식: 폴리곤 기반 인스턴스 마스크 · 클래스 3종 `crack`(0) · `efflorescence`(1) · `spall_detach`(2)
원칙: **보이는 것만 그린다.** 추정해서 연장하거나 메우지 않는다. 한 영상에 여러 결함이 있으면 결함마다 따로 그리고, 서로 겹쳐도 된다.

## ① 클래스 정의

| 클래스 | 한 문장 정의 |
|---|---|
| crack (균열) | 콘크리트 표면의 선형 · 분기형 · 망상형 불연속으로, 수분 · 유해물질의 침투 경로가 되는 것 |
| efflorescence (백태) | 수분 이동으로 표면 **위에** 생긴 백색 · 담색 침착물로, 누수나 지속적 수분 이동의 지표인 것 |
| spall_detach (박리 · 박락) | 표면층이 들뜨거나 벗겨진(박리) 또는 재료가 떨어져 나간(박락) 영역 — 영상에서 둘의 구분이 모호해 한 클래스로 묶음 |

- **spall_detach 재정의(v0.3, 논문강의 45쪽):** 한 클래스로 묶되 두 하위 유형을 기준서에 따로 적어 클래스 안 변동을 줄인다.
  - 박락: 재료가 떨어져 오목하고, 거친 단면 · 골재가 보이며 가장자리에 그림자가 진다.
  - 박리: 얇은 표면층이 판 모양으로 들뜨거나 벗겨져, **벗겨진 가장자리에 단차(경계선 · 그림자)**가 보인다. 흰색이어도 '얹힌 것'이 아니라 '벗겨진 것'이면 박리다.
- 데이터: 학습 원본 118장 기준 spall_detach 89개 · efflorescence 47개 · crack 31개 인스턴스(data_stats.md). spall_detach가 가장 많고 모양(둥근 정도 중앙값 0.64)도 가장 덩어리에 가깝다.

## ② 포함 기준

| 클래스 | 이렇게 보이면 라벨링한다 |
|---|---|
| crack | 폭이 고르지 않고 불규칙하게 꺾이거나 갈라지며 끝으로 갈수록 가늘어지는 어두운 선. 망상형(거북등), 보수재 위의 재균열 포함 |
| efflorescence | 흰 침착물이 표면 위에 두께감 있게 얹힘. 솜처럼 부푼 결정, 흘러내린 자국, 균열 · 이음부를 따라 번진 흰 띠 포함 |
| spall_detach | 박락(오목 + 거친 단면 + 그림자) 또는 박리(판 모양 들뜸 · 벗겨짐 + 가장자리 단차). 이음부 모서리 탈락 포함 |

## ④ 경계 규칙

| 클래스 | 폴리곤 경계 |
|---|---|
| crack | 균열선을 따라 **보이는 폭만큼 좁게**, 더 따라갈 수 없는 곳에서 멈춤. 이어진 균열(분기 포함)은 한 인스턴스, 떨어지면 별도 |
| efflorescence | 흰 침착물이 확실한 곳까지. 젖어 어두워진 주변 · 옅게 번진 가장자리는 제외. 떨어진 덩어리는 별도 인스턴스 |
| spall_detach | 박락: 깨진 가장자리(단면이 시작되는 선)를 따라 오목부 전체. 박리: 벗겨진 층의 가장자리 단차 안쪽. 노출 철근 포함 |
| 이음부 · 보수재 위 균열 | 이음선 · 보수재 띠는 빼고, 거기서 벗어나거나 띠 안에서 다시 갈라진 균열선만 crack (v0.2 판단보류 ①을 데이터 관행으로 확정) |
| **균열 + 백태 (v0.3)** | 흰 침착물이 균열선 **밖으로 면처럼 번져 보이면** 균열선 = crack + 흰 면 = efflorescence (겹쳐도 됨). **선만 보이면 crack만.** (검증 `USU013` 2장은 선만 보이는데 efflo로 라벨돼 있어 모델이 crack으로 답함 → ⑤ 재검토 목록) |
| **백태 ↔ 박리 (v0.3)** | 흰색이어도 가장자리에 단차가 있으면(벗겨진 것) spall_detach, 단차 없이 표면 위에 얹혀 있으면 efflorescence |

**crack 경계와 제공 데이터의 차이 (한계로 둔다 — 2026-11-20 결정):**
이 기준서는 v0.2와 같이 crack을 '보이는 폭만큼' 그린다. 그런데 제공 데이터의 crack 라벨은 균열을 넉넉한 띠로 감쌌다
(테스트 13장 중앙값: 라벨 띠 37px vs 실제 어두운 균열 픽셀 3px — 심화 ⑥, [guideline_v03_width.png](guideline_v03_width.png)).
학습 · 평가는 제공 라벨로 했으므로 모델의 crack 마스크는 띠 폭(예측/정답 0.99)을 따라가고, **이 모델의 마스크로 균열 폭을 잴 수는 없다.**
기준서를 데이터(띠)에 맞추는 대신 기준서는 그대로 두고, 이 불일치를 리포트의 한계로 적는다. 직접 주석한 2장(보이는 폭)과 제공 라벨의 IoU는 crack 0.580 · spall 0.729였다(2주차 ①).

## ⑤ 판단 보류

- 확신할 수 없는 영상은 임의로 라벨링하지 않고 [pending.csv](../week1/pending.csv)(파일 · 의심 클래스 · 보류 이유 · 날짜)에 적어 **별도 목록으로 분리**한다.
  ① 어둡거나 흐려서 확대해도 결함인지 모름 ② 결함은 맞지만 클래스를 정할 수 없음 ③ 하드네거티브인지 결함인지 정할 수 없음
- v0.2 보류 3건의 상태: 흰 실링재 띠 안의 재균열 → **해결**(④ 이음부 · 보수재 규칙) / 젖은 벽의 반사 + 백태 → 보류 유지 / 넓은 검은 물얼룩 → 보류 유지
- v0.3 새 보류 · 재검토 목록:
  - 테스트 `UWT015_2021_01_02_001_17710`: 백태 오른쪽 가는 흰 선 — 모델은 crack 0.66(테스트 FP 2). 실제 균열인데 라벨이 빠졌을 가능성(②)
  - 검증 `USU013_2022_03_16_002_483` · `USU013_2022_03_16_003_5020`: 선 모양 균열이 efflorescence로 라벨됨 → ④ '균열 + 백태' 규칙으로 재검토
  - 검증 `URT010_2022_02_08_001_2502` · `USU012_2021_02_07_005_2422`: 벗겨진 층 · V자 탈락이 efflorescence로 라벨됨 → ④ '백태 ↔ 박리' 규칙으로 재검토
- **라벨 누락 점검 절차 (v0.3):** 학습된 모델로 train 영상의 '라벨 없는 영역'에서 검증 임계값 이상 예측을 뽑아(심화 ③ 마이닝) 사람이 본다.
  이번에 108장 중 **13장이 라벨이 빠진 실제 결함**(거북등 · 망상 균열 7 · 박락 4 · 균열 2, adv3_hn_review.csv의 '뺌(실제 결함)')이었다.
  자동 마이닝 결과를 그대로 배경으로 쓰면 진짜 결함을 '결함 아님'으로 가르치게 되므로, 하드네거티브는 반드시 사람이 확인한 것만 쓴다.
